Global HL7 FHIR Lab — Alur Kerja Kolaborasi Bersama Tim

Perintah Anda dipisahkan dari tindakan sistem. Satu feature branch, satu PR yang dipilih, izin deployment terpisah.

1. Mulai pekerjaan

task <nama>
bun scripts/task-branch.ts

Task terkait tetap di feature branch aktif. Branch baru berasal dari development untuk pekerjaan terpisah yang disepakati.

Gunakan nama deskriptif seperti feat/kfa-normalization atau fix/org-address. Jangan menimpa working tree yang kotor.

↓

2. Ambil perkembangan tim

sync
bun scripts/sync-branch.ts

Feature branch menerima update origin/<branch> yang sama dengan fast-forward, lalu merge origin/development tanpa menulis ulang riwayat tim.

Tree yang kotor dihentikan dengan aman. File lokal yang diabaikan (ignored paths) diproteksi dari tabrakan incoming commit.

↓

3. Publikasikan commit

push
Hanya feature branch yang ditinjau.

Hanya dilakukan atas perintah eksplisit push. Stage file yang relevan dengan task: git add -- <files> lalu buat semantic commit.

Commit diunggah ke GitHub. Tidak melakukan direct push ke main atau development.

↓

4. Ajukan naskah perubahan

pr
bun scripts/create-pr.ts

Branch harus bersih, sudah di-push dan mencakup development terbaru. Precheck lokal (typecheck & rules) wajib lolos.

PR baru dibuat berstatus OPEN (ready for review) dengan target base development.

↓

5. Tunggu pengujian GitHub CI

Lihat tab Checks
gh pr checks <nomor>

Runner CI menjalankan Canonical CI: Structure, Rules Sync, TypeScript Typecheck, FHIR Conformance Tests (54 tests), dan Production Build.

Status berubah dari IN_PROGRESS menjadi SUCCESS atau FAILED. Setiap commit baru memicu pengujian ulang.

↓

6. Gabungkan satu PR yang dipilih

merge [PR]
Hanya setelah CI SUCCESS.

Wajib branch bersih, PR OPEN, SHA sesuai, dan Canonical CI SUCCESS. API error atau pending check menolak merge.

Merge menggabungkan feature PR ke dalam development. Tidak ada auto-deploy yang menyertai merge.

↓

7. Update integrasi atau siapkan rilis

deploy
Update staging / preview.

Deploy memperbarui environment staging dari branch development yang telah teruji.

Uji integrasi visual sandbox SIMRS, PGlite WASM engine, dan SQL-on-FHIR query runner di staging.

↓

8. Promosi dan deployment produksi

merge main
Lalu, jika diotorisasi:
deploy prod

merge main menyiapkan release PR dari development ke main dan menunggu Canonical CI lolos.

deploy prod mendispatch alur rilis produksi resmi. Membutuhkan otorisasi eksplisit terpisah dari perintah merge.

Prasyarat Keselamatan Operasional (Strict Safeguards)
1. DILARANG KERAS AUTO-PUSH: AI Agent tidak boleh melakukan git push tanpa perintah eksplisit "push".
2. DILARANG KERAS AUTO-MERGE: AI Agent tidak boleh me-merge PR tanpa perintah eksplisit "merge".
3. ZERO-DOCKER HOST DEV: Dev server lokal dijalankan murni di host Bun via bun scripts/local.ts atau .\scripts\local.ps1. PGlite berjalan via WASM di browser.
